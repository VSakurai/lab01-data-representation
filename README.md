## 1. Розміри типів даних (types.c)

| Тип       | Розмір (байт) | Розмір (біт) |
| :-------- | :------------ | :----------- |
| char      | 1             | 8            |
| short     | 2             | 16           |
| int       | 4             | 32           |
| long      | 4             | 32           |
| long long | 8             | 64           |
| float     | 4             | 32           |
| double    | 8             | 64           |
| void \*   | 8             | 64           |

**Відповіді:**

1. _Чи всі типи займають однакову кількість пам'яті?_ - Ні.
2. _Скільки бітів займає int?_ - 32 біти (4 байти).
3. **Який розмір має вказівник void \*?** - 8 байт (64 біти).
4. _Що це говорить про архітектуру?_ - Система 64-бітна (x86-64), оскільки розмір вказівника дорівнює 8 байтам.

## 2. Decimal → Hexadecimal → Binary (representations.c)

| Decimal | Hexadecimal | Binary                              |
| :------ | :---------- | :---------------------------------- |
| 10      | 0xA         | 00000000 00000000 00000000 00001010 |
| 65      | 0x41        | 00000000 00000000 00000000 01000001 |
| 127     | 0x7F        | 00000000 00000000 00000000 01111111 |
| 255     | 0xFF        | 00000000 00000000 00000000 11111111 |
| 256     | 0x100       | 00000000 00000000 00000001 00000000 |
| 1024    | 0x400       | 00000000 00000000 00000100 00000000 |

**Відповідь:** `65`, `0x41` та `01000001` — це одне й те саме значення, просто записане у різних системах числення (десятковій, шістнадцятковій та двійковій).

## 3. Символи (characters.c)

| Character | Decimal | Hex  |
| :-------- | :------ | :--- |
| A         | 65      | 0x41 |
| B         | 66      | 0x42 |
| a         | 97      | 0x61 |
| 0         | 48      | 0x30 |
| 9         | 57      | 0x39 |

**Відповідь:** У змінній `char c = 'A';` зберігається **числове значення 65**. Комп'ютер не розуміє символів, він працює лише з числами. Літера 'A' — це інтерпретація числа 65 за таблицею ASCII.

## 4. Signed та Unsigned (signed_unsigned.c)

**Прогноз для -1:** Я очікував побачити `11111111` (доповняльний код).

**Пояснення:** Число `11111111` (0xFF) може означати як 255, так і -1, залежно від типу. Для `uint8_t` це 255, для `int8_t` — -1 (оскільки старший біт є знаковим). Тип даних визначає, як інтерпретувати ці біти.

## 5. Overflow (overflow.c)

**Прогноз:** 255 + 1 = 256. Але оскільки `uint8_t` — це 8-бітне беззнакове число (максимум 255), я очікував переповнення і результат 0.

**Результат:** Після `value++` значення стало `0`.

**Пояснення:** 8 біт можуть представляти 2^8 = 256 різних значень (від 0 до 255). При додаванні 1 до 255 всі біти перетворюються на 0.

## 6. Пам'ять та Endianness (memory.c)

**Прогноз:** Я очікував побачити байти у порядку `78 56 34 12` (Little-endian) або `12 34 56 78` (Big-endian).

**Результат:** Байти розташовані як `78 56 34 12`. Наймолодший байт (0x78) знаходиться за найменшою адресою.

**Висновок:** Система використовує **Little-endian**. Саме число `0x12345678` не змінилося — змінився лише порядок його байтів у пам'яті.

## 7. Фінальна програма (inspect.c)

Програма приймає число від 0 до 255 і виводить його в decimal, hex, binary та character. Також вона досліджує 32-бітне значення `0x12345678` і автоматично визначає порядок байтів системи.
